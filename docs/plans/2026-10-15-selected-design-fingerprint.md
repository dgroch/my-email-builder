# Bind publishing to the selected saved design

The approved publishing contract requires exporting the exact saved design selected by the editor. The existing timestamp-only check cannot establish that invariant for Notion storage: reads span page metadata and body requests, updates replace multiple blocks, direct body edits need not change Updated, and concurrent saves can share a timestamp.

Correct the existing boundary with a required SHA-256 expectedDesignHash alongside expectedUpdatedAt. Hash canonical JSON of id, name, updatedAt, subjectLine, previewText and campaign, using the existing canonical serializer. Exclude presentation links and operational metadata that cannot affect rendered creative. Expose the hash with full saved-design responses only. The UI already compares campaign/subject/preview to the open editor before navigation; carry the response hash on that navigation and persist it in the engine import request/idempotency fingerprint.

Builder export must compare the hash of the design object it actually freezes to expectedDesignHash before reserving/rendering. Engine must independently recompute the same hash from verified artifact provenance.design before preparing/uploading assets. Existing provenance already binds the entire saved design, components and brand, so the artifact schema need not change. Retain timestamp comparison as an additional check. Missing/malformed hashes fail closed; no timestamp-only fallback for new requests or old queued requests. Existing verified immutable artifacts remain readable. No storage migration, customer import or message send.

Regression evidence must cover same-timestamp changed campaign, subject/name changes, JSON object key reordering, array order, missing fingerprint, idempotency conflicts, propagation across UI/API/worker, and a builder returning an otherwise valid artifact for a different source hash. Verify refusal occurs before asset writes or campaign creation. Two saves with identical selected payloads may share a hash: they produce the same selected content. Component/brand snapshots keep their existing export-time semantics; this correction does not claim they were frozen at editor navigation.

Implement in builder PR43 and a paired engine fix branch from current main. Run meaningful unit and PostgreSQL integration suites and independent review. Deploy only with concrete release authority; both installation revisions must be updated together. During mixed versions import requests fail closed rather than silently weakening the check. After release, reuse the retained synthetic fixture, verify actual Notion create/read/export, duplicate/stale behavior and the staff import flow. Native draft/reply credential and email-client proof remain separate gates.
